## 3D Texture Nodes

### Bump Map (3Bu)
Converts a grayscale height-map image into a bump map (or accepts an existing Create Bump Map output) and outputs a material. (p. 851-853)
- Inputs: `ImageInput` (orange) — a 2D RGBA image (as height map) or the output of a Create Bump Map node.
- Key controls: **Source Image Type** — **Height Map** (generates bump data, like Create Bump Map) vs **Bump Map** (expects pre-made Create Bump Map output) - **Filter Size** — dropdown; size of the custom filter generating bump info - **Height Channel** — which channel supplies grayscale height data - **Clamp Z Normal** — clips low values of the resulting blue channel - **Height Scale** — contrast/visibility of the bump effect; higher = more visible - **Texture Depth** — optionally converts output bit depth - **Wrap Mode** — wraps image at borders so filtering works correctly on seamless tiling textures.
- Gotchas: See Mental Model #8 for the Height Map / Bump Map / Normals Map terminology distinction (p. 853) — get "Source Image Type" wrong and the bump data will be misinterpreted.

### Catcher (3Ca)
"Catches" **texture-mode** projections from a Projector 3D or Camera 3D and turns them into a texture map applied via this material. (p. 854-856)
- Inputs: **none** — output connects directly to a material input (e.g., a Blinn/Cook-Torrance diffuse color input, or specular/reflection/refraction inputs — not restricted to diffuse).
- Key controls: **Enable** — enables/disables just the effect (distinct from the node's red master switch, which also stops Settings-tab scripts) - **Color Mode** — how to combine light from multiple projectors (no effect with only one projector; only affects the **Software renderer** in Renderer3D, not OpenGL) - **Alpha Mode** — same, but for combining Alpha from multiple projectors (Software renderer only) - **Threshold** — excludes low values from the accumulation calc (e.g. Median Accumulation mode with Threshold 0.01 excludes pixels <0.01) - **Restrict by Projector ID** — only receives light from projectors with a matching ID - **Material ID**.
- Gotchas: **Requires** a Projector 3D or Camera 3D in the scene set to project in **Texture mode** onto the same geometry the Catcher feeds. Without that, or if projection mode is Light/Ambient Light instead of Texture, the Catcher-fed object renders **transparent and invisible** (p. 854, 856). Advantage over Light-mode projection: Catcher respects the projected image's Alpha (so masked/rotoscoped windows in a projected building image, for example, can become transparent) — Light-mode projection ignores Alpha entirely.

### CubeMap (3Cu)
Builds a texture/environment map from either six separate face images or one unfolded cross-layout image; used for environment maps (skies, horizons) or reflection/refraction maps. (p. 856-859)
- Inputs (depend on **Layout** setting): `CrossImage` (orange; default, or when Layout = Vertical/Horizontal Cross) — single 2D image - `CubeMap.[DIRECTION]` (six separate multi-colored inputs; only when Layout = Separate Images) — one image per face (left/right/top/bottom/front/back).
- Key controls: **Layout** — **Separate Images** (6 inputs; non-square/mismatched images are rescaled to the largest common 1:1 size) - **Vertical Cross** (1 input; expects height > width, ~3:4 aspect, else cropped) - **Horizontal Cross** (1 input; expects width > height, ~4:3 aspect, else cropped). **Coordinate System** — **Model** (object local space) - **World** (global space) - **Eye** (camera/viewer space). **Rotation** — axis-order buttons (e.g. XYZ) plus dials rotating the texture around its pivot. **Warn About Bad Dimensions** — checkbox; logs a console warning if the input image doesn't match the selected layout's expected dimensions. **Material ID**.

### Falloff (3Fa)
Blends two materials/textures based on the **incidence angle** between the camera and the surface — one look for parts facing the camera, another for parts facing away/into the scene. (p. 859-861)
- Inputs: `Face On Material` (orange; 2D image → diffuse texture on basic material) — used for surface facing the camera - `Glancing Material` (green; same image handling) — used for surface facing away, into the scene. Output is always a material.
- Key controls: **Color Variation** — **Two Tone** (two flat Color controls for Face On / Glancing) or **Gradient** (a gradient control drives both — usable for toon-shader-style effects) - **Face On Color** — multiplies the Face On texture if present; reducing opacity reduces color+Alpha of the Face On material - **Glancing Color** — same, for the Glancing side - **Falloff** — controls the transition sharpness between Glancing and Face On (gamma-like blend) - **Material ID**.
- Gotchas: Useful to switch between, e.g., a Blinn look and a Reflect look depending on view angle (manual's own example, p. 861).

### Fast Noise Texture (3FN)
Procedural, resolution-independent 3D-native equivalent of the 2D Fast Noise node; outputs a material directly. Supports a 3D volumetric mode for seamless texturing when paired with nodes providing UVW coordinates (e.g. UV Map set to XYZ-to-UVW or Camera). (p. 861-863)
- Inputs: `SourceMaterial` (optional) — a 2D image or 3D material to be altered by the noise pattern.
- Key controls: **Output Mode** — **2D** (UV-based; supports smooth animation of the pattern) or **3D** (UVW-based; geometry like Shape 3D auto-provides the third coordinate, or use a UV Map node; **does not support pattern animation**) - **Detail** — more layers of finer noise; higher = longer render, more natural result (not all GPUs support high Detail in hardware) - **Brightness** - **Contrast** (exaggerates the noise) - **Scale** — noise scale along UV - **Scale Z** (3D only) — scale along the W axis (perpendicular to the UV plane) - **Seethe** (2D only) — smoothly varies the pattern - **Seethe Rate** (2D only) — per-frame animated drift rate, no keyframes needed - **Discontinuous** — checkbox; creates hard discontinuity lines instead of smooth interpolation - **Invert** — inverts the noise (most effective combined with Discontinuous) - **Material ID**.

### Gradient 3D (3Gd)
Textures objects with gradient patterns; shares many controls with the 2D Background node's gradient. Cannot be transformed directly in 3D space — orient it via **Texture Transform** (per-pixel) or, preferably, **UV Map** in XYZtoUVW mode (per-vertex, faster, has onscreen controls). Default gradient runs -1 to +1 along the Z axis; Shape 3D primitives all output a third (W) texture coordinate for this. (p. 864-866)
- Inputs: none. Output connects to a material input.
- Key controls: **Gradient Type** — **Linear** - **Reflect** (linear, mirrored at the midpoint) - **Square** - **Cross** (like Reflect but across two axes) - **Radial** (circular). **Gradient Bar** — add/edit/remove color stops (animatable position and color); supports a **From Image** modifier to derive the gradient from an image. **Interpolation Space** — default linear RGB interpolation; switch color space if you get unwanted intermediate colors. **Scale** — sizes the gradient. **Offset** — pans through the gradient. **Repeat** — **Once** (border colors hold their edge value when panned — can produce a flat white/black border) - **Repeat** (border wraps, producing a sharp jump) - **Ping Pong** (border fades back toward the opposite end). **Sub Pixel** — accuracy of gradient generation. **Material ID**.

### ReliefMap (3RM)
Generates height-based surface detail on 3D shapes by eroding/displacing based on a companion **CreateReliefMap**-processed image; alters normal/displacement mapping. Unlike simple bump maps, **ReliefMap can self-occlude**, producing natural lighting interactions without hand-modeling geometric detail. RGB channels store normals; Alpha stores height/depth. (p. 867-868)
- Inputs: `Background Input` (yellow) — a material (Blinn/Ward/Cook Torrance/Phong) - `ReliefMap Input` (white) — a 2D image processed through **CreateReliefMap** first.
- Key controls: **Depth Scale** — expands/contracts overall relief depth - **Lock U/V** — on = uniform U/V scaling; off = independently adjustable per-channel frequency - **Map Type** — **Relief** vs **Cone** (Cone = better quality and faster shading, at higher performance cost) - **Quality** — fine-tunes result quality, most visible with Relief map type.
- Gotchas: Requires the separate **CreateReliefMap** node upstream to prep the image — ReliefMap itself does not accept a raw height image directly per this slice's inputs description.

### Sphere Map (3SpM)
Builds simulated (non-raytraced) 360° environment/reflection mapping from an equirectangular image — much faster than raytracing a fully reflective scene, with little accuracy loss. Typically feeds a Reflect node's Reflection Color input. (p. 869-871)
- Inputs: `ImageInput` (orange) — a 2D RGBA image, ideally equirectangular (X = 0-360° longitude, Y = -90 to +90° latitude).
- Key controls: **Angular Mapping** — remaps latitude from hemispherical-fisheye to angular-fisheye so poles are less squashed and texture area maps more evenly onto the sphere (easier to paint/edit) - **Rotation** — rotates the texture map - **Material ID**.
- Gotchas: Expects a 2:1 aspect image; otherwise: if `2 * width > height`, width is fit and poles get clamped edges; if `2 * width < height`, height is fit and there's clamping around the 0° longitude line. **Connecting an equirectangular texture directly to a sphere instead of through Sphere Map** produces different results when start/end angle or latitude is <360°/180° — direct connection *squashes* the texture, whereas Sphere Map *crops* it; direct connection also **mirrors the image horizontally** (fix with an upstream Transform node) (p. 871).

### Texture 2D (3Tx)
Sets UV texture-map metadata on an image (default UV span is (0,0) to (1,1)); relies on U/V Map channels existing in 3D-rendered images — has no effect if those channels are absent. (p. 871-873)
- Inputs: `Image Input` (orange) — a 2D image.
- Key controls: **U/V Offset** — shifts the texture along U/V - **U/V Scale** — scales the texture along U/V - **Wrap Mode** — **Wrap** (edges wrap around) - **Clamp** (edge color repeats outward, like Transform node's Duplicate mode) - **Black** (clipped to black, Alpha 0) - **Mirror** (mirrored in both X and Y) - **Texture Filtering Mode** — **Nearest** (fastest, can artifact when scaling) - **Bilinear** (standard isotropic scaling, good for magnification) - **Trilinear** (better for scaling down) - **Anisotropic** (highest quality; accounts for camera orientation/polygon perspective) - **SAT** (Summed Area Table; highest-quality filtering, more memory, best on smaller bitmaps).
- Gotchas: Background pixels can have U/V = 0.0, which pulls the texture's corner-pixel color onto them — mask by Alpha, Object ID, or Material ID to keep texturing to intended objects only. Prefer the **UV Map** tool over Texture 2D where applicable — faster, with onscreen controls (p. 871, 873).

### Texture Transform (3TT)
Translates/rotates/scales the UVW texture coordinates of a 3D object; input can be an image, but output is always a material. (p. 873-875)
- Inputs: `Material Input` (orange) — 2D image or 3D material to transform.
- Key controls: **Translation** — U, V, W sliders - **Rotation** — Rotation Order buttons + UVW dials - **Scale** — U, V, W sliders - **Pivot** — U, V, W pivot point for rotation/scaling - **Material ID**.
- Gotchas: Not all Wrap modes are supported on all graphics cards (p. 874). Prefer UV Map (XYZtoUVW) over Texture Transform when per-vertex control suffices — it's faster (see Mental Model #11).

## Gotchas and non-obvious behavior
- Selecting/loading a light node directly into the viewer shows nothing — you must view a Merge 3D (or later) node that the light feeds.
- Directional Light and Point Light shadows require **Hardware Renderer**; Spot Light shadows work with **either** Hardware or Software Renderer (Renderer3D node's Rendering Type setting).
- **Force All Materials Non-Transmissive** on a light trades away colored/"stained glass" shadows for a much cheaper Z-only shadow map (~1/5 memory).
- Opacity and Transmittance are independent: a surface can be fully opaque yet transmit 100% of incoming light (effectively emissive-looking) — don't assume Opacity=1 means "blocks all shadow-transmission."
- Two-Sided Lighting only adds normals for lighting purposes; Fusion never culls backfaces by default, so you already see through single-sided geometry from behind (as a duplicated front face) even without enabling it.
- A transparent, two-sided surface lit from the back looks **unlit** when viewed from the front — a specifically called-out point of confusion (repeated verbatim across Blinn/Cook Torrance/Phong/Ward/OpenPBR docs).
- Catcher has no inputs of its own and goes fully invisible/transparent if there is no upstream Projector 3D/Camera 3D actively projecting in **Texture** mode onto the same geometry.
- Catcher's Color Mode / Alpha Mode (multi-projector accumulation) only matter for the **Software renderer** — they have no effect under OpenGL.
- CubeMap's Vertical/Horizontal Cross layouts auto-crop non-conforming aspect ratios rather than erroring — turn on **Warn About Bad Dimensions** to get a console notice.
- Sphere Map vs. direct-to-sphere texture connection is not equivalent when using partial angle/latitude ranges: Sphere Map crops, direct connection squashes and also mirrors horizontally.
- Every multi-input material node with same-colored ports (Blinn, Cook Torrance, Phong, Reflect, Ward) supports **Option/Alt-drag-and-hold** (or right-mouse-button drag) onto the node tile to get an exact-input picker menu — the standard technique for precise wiring when several inputs share a color.
- OpenPBR's Ambient Occlusion input only has effect with a **DomeLight or AmbientLight** present in the scene.
- Import Transform (Transform tab) only imports transform data (position/rotation/scale) from `.lws`/`.ase`/`.ma`/`.xsi` — for actual geometry, lights, or cameras use **File > FBX Import** instead.

## Recipes / workflows
1. **Set up a basic shadow-casting spotlight rig**: Add a **Spot Light [3SL]** → connect into a **Merge 3D** with your geometry → set **Cone Angle** and **Penumbra Angle**/**Dropoff** for the beam shape → confirm **Enable Shadows** is on (default) → set **Renderer3D** Rendering Type to Hardware or Software → tune **Shadow Map Size** up if edges look blocky, then adjust **Multiplicative Bias** then **Additive Bias** if you see self-shadowing artifacts or a detached shadow.
2. **Build a reflective/glass material**: Create a **Sphere Map [3SpM]** (or **CubeMap [3Cu]**) fed by an equirectangular (or six-face) environment image → connect its output to a **Reflect [3RR]** node's **Reflection Color Material** input → set **Reflection Strength Variability** to **By Angle** and tune **Face On Strength** / **Glancing Strength** / **Falloff** for a Fresnel-like edge brightening → drop the **Background Material** opacity below 1 and enable **Separate RGB Refraction Indices** for glass dispersion → optionally set **Refraction Tint** for colored glass → connect Reflect's output as the diffuse input of a **Ward** or **Blinn** node (or use Reflect standalone) for the final material.
3. **Add surface micro-detail without modeling it**: Route a 2D texture through a **Bump Map [3Bu]** node (set **Source Image Type** to Height Map for a raw grayscale height image, or Bump Map if it already came from Create Bump Map) → connect the Bump Map node's output to the **Bump Map Material** input on Blinn/Cook Torrance/Phong/Ward/Reflect. For self-occluding relief instead of flat bump: run the source image through **CreateReliefMap** first, then into **ReliefMap [3RM]**'s white input, with your base material into its yellow input.
4. **Project a masked image onto geometry as a texture (not light)**: Set a **Projector 3D** or **Camera 3D**'s projection mode to **Texture** (not Light/Ambient Light) → connect a **Catcher [3Ca]** node's output into the diffuse color (or other) material input of the target geometry's shader → this respects the projected image's Alpha, unlike Light-mode projection which ignores Alpha entirely.

## Scripting and automation hooks
- Toolbar/search abbreviations (usable in the Select Tool dialog and scripting references): `3AL` Ambient Light, `3DL` Directional Light, `3Do` DomeLight, `3PL` Point Light, `3SL` Spot Light, `3Bl` Blinn, `3Bol` Channel Boolean, `3CT` Cook Torrance, `3MM` Material Merge 3D, `3OP` OpenPBR, `3Ph` Phong, `3RR` Reflect, `3SMM` Stereo Mix, `3Wd` Ward, `3Bu` Bump Map, `3Ca` Catcher, `3Cu` CubeMap, `3Fa` Falloff, `3FN` Fast Noise Texture, `3Gd` Gradient 3D, `3RM` ReliefMap, `3SpM` Sphere Map, `3Tx` Texture 2D, `3TT` Texture Transform.
- Named input IDs given verbatim in this slice (usable for `SetInput`/`ConnectInput` by name where the API exposes named inputs): `SceneInput` (all lights), `DomeTexture` (DomeLight), `LeftMaterial` / `RightMaterial` (Stereo Mix), `ImageInput` (Bump Map, Sphere Map, Texture 2D calls it `Image Input`), `CrossImage` (CubeMap), `CubeMap.[DIRECTION]` (CubeMap's six per-face inputs, e.g. left/right/top/bottom/front/back), `BackgroundMaterial` / `ForegroundMaterial` (Channel Boolean; Material Merge 3D's equivalents are documented only as "Background Material"/"Foreground Material" labels).
- Import Transform file formats accepted: `.lws` (LightWave Scene), `.ase` (Max Scene), `.ma` (Maya Ascii Scene), `.xsi` (dotXSI). Full-scene import (geometry/lights/cameras) instead uses **File > FBX Import**.
- Keyboard shortcuts: **Q** = translate mode, **W** = rotate mode, **E** = scale mode (onscreen Transformation Widget, common to 3D Transform tab tools). **Option (macOS) / Alt (Windows)** held during a drag-and-drop connection (or a right-mouse-button drag) onto a densely-ported node tile opens an exact-input picker menu.
- Every material/texture node's **Material ID** slider and every node's **Comments**/**Scripting** tab are standard, scriptable per-tool controls (Scripting tab holds render-time script edit boxes — consult the separate scripting documentation for exact hook names, not detailed in this slice).
- No explicit numeric default values are stated in this slice for most sliders (Intensity, Cone Angle, Penumbra, Roughness, etc.) beyond the illustrative "0.2 = 20%" intensity example repeated for every light type, and Cone Angle's stated **90° maximum**. Treat unstated ranges/defaults as unknown rather than inferring — verify in the live Inspector before scripting exact values.
