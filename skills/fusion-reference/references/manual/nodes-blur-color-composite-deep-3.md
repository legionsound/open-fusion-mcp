## Composite Nodes (Chapter 35, p.976-994)

### Dissolve (`DX`)
Mixes/transitions two images via a Background/Foreground slider; can also act as an automatic layer-switcher. (p.977)
- Inputs (all optional): Background; Foreground; **Gradient Map** (only needed for Gradient Wipe operation).
- Key controls: `Operation` — **Dissolve** (standard cross-dissolve) / **Additive Dissolve** (adds 2nd clip in, then fades 1st out — film-look) / **Erode** (grows dark areas of background to reveal foreground, "burning filmstrip" look) / **Random Dissolve** (static random-dot pattern mix) / **Random Noise Dissolve** (moving random-dot pattern) / **Gradient Wipe** (dissolve driven by luminance of the Gradient Map input — feed it shapes, gradients, fire/water/rain footage, Fast Noise, or particles; can soften edges, add a colored border) / **SMPTE Wipe** (classic switcher-style horizontal/vertical wipe; softenable, borderable). `Background/Foreground` slider — default Foreground; determines mix percentage (extreme positions act as a hard switch); if only one input is connected, that one outputs regardless of slider position. Gradient/SMPTE-only: `Wipe Style` (SMPTE: Horizontal L-R / Vertical T-B) + `Invert Wipe`; `Softness`; `Border` + `Border Softness` + `Border Color`.
- Gotchas: unlike most nodes, Dissolve doesn't require Background connected before Foreground, and can output either input alone — this lets you feed two clips of different duration into BG/FG, set the slider to fully favor the shorter clip, and the node auto-switches to the other clip once the short one's last frame ends (an automatic layer-switching trick). **Resolution handling**: if the slider sits at a full extreme, output resolution = that input's resolution; if mixed between extremes with mismatched input resolutions, output resolution jumps to the *larger* of the two — e.g. dissolving a 4K background against an 8K foreground outputs 4K at full-Background but suddenly jumps to 8K the instant the slider leaves that extreme. (p.977-979)

### Merge (`Mrg`)
The primary compositing node: combines background + foreground via Alpha, with Porter-Duff-style Operator modes and Apply-Mode blend math, plus optional Z-depth compositing. (p.980)
- Inputs (all optional, but background should be connected before foreground): **Background** (orange — connecting FG alone with no BG connected outputs nothing); **Foreground** (green); **Effect Mask** (masks where the merged result shows vs. background-only).
- **Output resolution = the Background input's resolution.** Use a Crop node to resize the "canvas" without resizing the image content, or Resize to change both. (p.980-981)
- Merge tab — Foreground Sizing: `Center X/Y` (default 0.5/0.5 = centered; values shown in normalized coords scaled by Reference Size), `Size` (0.0-5.0 slider range, but any positive value can be typed; 1.0 = pixel-for-pixel), `Angle` (rotates FG before compositing).
- `Apply Mode` — the full blend-mode list: Normal (default; Alpha-masked, reveals `Operator` submenu — see below), Screen (multiplies inverted values, ignores Alpha and layer order, always lightens; also reveals Operator submenu), Dissolve (averages the two images), Darken, Multiply, Color Burn, Linear Burn, Darker Color (compares composite RGB, not per-channel like Darken), Lighten, Color Dodge, Linear Dodge (Add), Lighter Color (composite-RGB version of Lighten), Overlay, Soft Light, Hard Light, Vivid Light (extreme Overlay/Soft Light — usually needs reduced opacity), Linear Light (Linear Dodge on lights + Linear Burn on darks — usually needs reduced opacity), Pin Light (simultaneous Darken+Lighten, removes midtones), Difference, Exclusion (lower-contrast Difference), Hue, Saturation, Color (luminance of BG + hue/saturation of FG — good for tinting monochrome), Luminosity (inverse of Color mode), **Hypotenuse** (for HDR out-of-range colors: `Out = sqrt(Fc² + Bc²)`), **Geometric** (for HDR out-of-range colors: `Out = 2*Fc*Bc / (Fc+Bc)`).
- `Operator` submenu (visible only when Apply Mode = Normal or Screen) — general formula `(fg * x) + (bg * y)`: **Over** (x=1, y=1-fgAlpha — standard composite), **In** (x=bgAlpha, y=0 — clips FG to BG's mask, FG color only), **Held Out** (x=1-bgAlpha, y=0 — opposite of In), **Atop** (x=bgAlpha, y=1-fgAlpha — FG shows only where BG has matte), **XOr** (x=1-bgAlpha, y=1-fgAlpha — combines wherever *either* has matte, never where *both* do), **Conjoint** (decision-based combination good for soft/motion-blurred alpha: `x=1, y=x+y(1-af)/ab if af>ab`), **Disjoint** (decision-based combination that avoids out-of-range alpha, correct premultiplied edges: `x=x+y(1-af)/ab, y=x+y if af+ab<1`), **Mask** (`x=x*af, y=0` — outputs BG multiplied by FG alpha), **Stencil** (`x=x*(1-af), y=0` — outputs BG multiplied by inverse FG alpha), **Under** (same math as Over with FG/BG swapped: `x=y, y=x*(1-af)`). Modes not directly listed (Under, In, Held In, Below) are obtainable by swapping FG/BG (Cmd/Ctrl-T) and picking the corresponding listed mode. Reference: Porter & Duff, *Compositing Digital Images*, ACM SIGGRAPH Computer Graphics, 1984, pp.253-259.
- `Subtractive/Additive` slider — blends between Additive (assumes premultiplied FG) and Subtractive (assumes non-premultiplied FG, multiplies by its own alpha first) merge math; useful to fix edges that read too bright or too dark. `Alpha Gain` — linearly scales FG alpha; in Subtractive mode controls density like Blend; in Additive mode reduces how much BG is obscured (brightens overall result; at Alpha Gain 0.0 in Additive mode, FG pixels are simply added to BG). `Burn In` — adjusts how much Alpha darkens the BG independent of FG amount added (0.0 = straight alpha blend; 1.0 = FG effectively added onto BG; for Additive merges, increasing Burn In ≡ decreasing Alpha Gain). `Blend` — cloned Common Controls Blend slider; blends the merged result back toward BG.
- Additional controls — `Filter Method` (for resized inputs): Nearest Neighbor (fastest/crudest) / Box / **Linear (default)** / Quadratic / Cubic / Catmull-Rom (adds sharpening, good for downscale detail preservation) / Gaussian / Mitchell (like Catmull-Rom, better on fine detail, slower) / Lanczos (like Mitchell/Catmull-Rom, cleaner, slower) / Sinc (very sharp, can ring) / Bessel (like Sinc, slightly faster); Sinc/Bessel reveal a `Window Method`: Hanning / Hamming / Blackman (sharper falloff) / Kaiser (between Hamming and Blackman). `Edges` buttons (for FG smaller than canvas DoD): Canvas (fills with the canvas color/opacity — pipe a Set Canvas Color node ahead of the FG input to customize) / Wrap (tiled "video wall") / Duplicate (stretches edge pixels outward) / Mirror (duplicate but flips/flops alternate tiles). `Invert Transform` — inverts position/rotation/scale (useful when the Merge is driven by a tracker, for match-move). `Flatten Transform` — stops this node's transform from concatenating with the *next* node (it can still concatenate transforms from upstream). `Reference Size` — `Use Frame Format Settings` (adopt the composition's frame format) or manual `Width`/`Height`: lets the Center control display actual pixel coordinates instead of normalized 0-1 values (internal storage is still normalized 0-1; scripting/publishing reads the normalized value regardless of this display setting).
- Channels tab: `Perform Depth Merge` — off by default; when on, uses both images' Z-channels (if present — ignored otherwise) to order compositing front-to-back while Alpha still governs transparency. `Foreground Z-Offset` (+ Sample pick) — offsets FG's Z value; raise to push FG farther away, lower to bring closer. `Subtractive/Additive` (Channels-tab version) — when Z-compositing causes BG pixels to show through FG (because BG's Z is nearer for that pixel), controls whether those pixels merge Additively or Subtractively, same semantics as the Merge-tab slider. (p.980-988)

### MultiMerge (`MMrg`)
Layer-based stack of Merge operations in one node — replaces scattering many standalone Merge nodes through the tree; each new source dragged onto the node creates its own Foreground input + Layer List entry. (p.989)
- Inputs: Background (orange, connect first); Foreground (white — new one auto-created per dragged connection); Effect Mask.
- **Output resolution = Background input's resolution** (same rule as Merge).
- Layer List: top-to-bottom = front-to-back stacking order (closest-to-FG at top). Click to select (Shift = range select, Cmd = multi-select non-adjacent); selecting a layer surfaces its own independent Merge controls (identical to the Merge node's Merge tab) at the bottom of the Inspector, and glows that layer's node-tree pipe. Right-click menu: `Go To Source` (selects/opens the upstream tool feeding this layer), `Split Here` (spins the selected layer + everything above it into a new, chained MultiMerge node), `Rename Layer` / `Rename Layer to Match Source`, `Set Layer to Default` (resets that layer's Merge settings), `Delete Layer` (removes from list + disconnects pipe, does not delete the upstream tool). Drag a layer name to reorder. Checkbox next to a layer's name enables/disables it (keeps it in the list, contributes nothing to composite while off). Disconnecting a layer's pipe leaves a strikethrough placeholder in the list — lets you audition different sources into the same layer slot without rearranging order. **Layer List itself is keyframable** — order and enable/disable state can both be animated over time. (p.989-992)

### Composite Nodes Common Controls (Settings tab, p.992-994)
Same as Blur's Common Controls (Blend, Process When Blend Is 0.0, RGBA post-selector, Apply Mask Inverted, Multiply by Mask, Use Object/Material + Correct Edges, Object/Material ID sliders, Use GPU, Motion Blur group, Comments, Scripts) — **no Clipping Mode here** — **plus a unique `Layers` group**: `Process Layers` — Default Layer (base/unnamed layer only) / All Layers / Custom (pick specific named layers); `Input Layer` (lists layers available from the default input's upstream node, for isolating one layer downstream); `Effect Mask Layer` (available layers usable as mattes, if the tool has an Effect Mask input).

## Deep Image Nodes (Chapter 36, p.995-1023) — Studio only

**What deep compositing is**: Deep image data (notably in OpenEXR) stores *multiple samples per pixel* representing objects at different depths within the same pixel — unlike a normal 2D image's single value per pixel. Fusion's deep toolset (all prefixed `d`) uses this to correctly layer/composite complex 3D renders where multiple objects overlap in depth, without the aliasing/ordering problems a flat 2D Z-buffer composite would have. Renderer3D nodes can output deep data; Loader/MediaIn can import deep EXRs; Saver can export deep EXRs. **Every deep tool except Image to Deep and Deep to Image will auto-convert a plain 2D input into deep data.** Deep compositing requires a **linear colorspace**; convert to your desired colorspace only after merging. Right-click any deep node → **Cache to Disk** to bake a deep composite to disk (reduces live computation load on complex scenes). (p.996)

- **dColorCorrector (`dCC`)** — Deep-image equivalent of the 2D Color Corrector: same Correction submenu (Colors/Levels/Histogram/Suppress), same Range (Shadows/Midtones/Highlights/Master) and Ranges-tab spline system, same Suppress color wheel. Inputs: Input (yellow, required, deep); Effect Mask (blue). Notably **only 2 inputs** — no Match Reference/Match Mask green/white inputs as on the 2D Color Corrector. Options tab: Histogram Proxy Scale, Process Order, Apply Mask Inverted. Its own Settings tab documents `Clipping Mode` (Frame/Domain/None) directly, rather than deferring to the chapter's shared Common Controls. (p.996-1005)
- **dCrop (`dCr`)** — crops deep samples by Z range and/or an input mask. Controls: `Use Minimum Z` / `Use Maximum Z` (checkbox + slider + Sample pick each); `Keep Outside Depth Range` (inverts the crop selection). Inputs: Input (orange, deep); Effect Mask (blue). (p.1006-1007)
- **Deep to Image (`DTI`)** — flattens deep samples into a normal 2D image for downstream 2D compositing. Controls: `Flip Depth`; `Volumetric Composition` (blends overlapping samples as semi-transparent volumes rather than flat surfaces — for realistic fog/VDB-style interaction). Image tab: `Process Mode` (fields), `Depth` (color bit depth of output — float allows HDR beyond 0-1), `Source Color Space` (Auto/Space — tags metadata for a downstream Gamut node or Saver, doesn't itself convert), `Source Gamma Space` (Auto/Space/Log) + `Remove Curve`, `Pre-Divide/Post-Multiply`. Input: Input (orange, deep, required, no mask input listed). (p.1007-1009)
- **Deep to Points (`DTP`)** — converts deep samples into a 3D point cloud for visualizing Z distribution. Inputs: Input (orange, deep, required); **Camera** (green — a 3D scene/camera for accurate point placement in the 3D Viewer). Controls: `Style` (crosshairs/points), `Size`, `Antialiasing`, `Density`, `Default Color` vs `Use Per-Point Colors`, `Make Renderable` (+`Unseen by Camera` — visible in viewer, not in Renderer3D output), `Scale`, `Depth Scale`, `Flip Depth`. Transform tab: standard 3D Translation/Rotation(+Order)/Pivot/Scale(with Lock X/Y/Z) controls, `Use Target`, `Import Transform` (loads `.lws`/`.ase`/`.ma` — **transform data only**, not geometry/lights/cameras; use File > FBX Import for those). (p.1010-1013)
- **dHoldout (`dHld`)** — uses a foreground deep image to occlude background deep samples. Inputs: Background (orange, deep); Foreground (white, deep occluder). Controls: `Compute Occluded Samples` (recolors visible background as if seen through a semi-transparent foreground, rather than just removing occluded samples); `Holdout Z Offset` (+ Sample pick — negative pushes holdout forward, positive back); `Holdout Center X/Y`. (p.1014-1015)
- **dMerge (`dMg`)** — merges multiple deep streams' depth samples for seamless compositing (deep equivalent of Merge 3D). Inputs: Background (orange, deep); Foreground (white — drag additional connections to add more foreground inputs; no cap mentioned). No unique controls beyond the shared Settings tab. (p.1015-1016)
- **dRecolor (`dRc`)** — recolors deep samples using a standard 2D RGB(A) image. Inputs: Depth (orange, deep); Color (green, 2D RGB). Controls: `Center X/Y` (reposition the 2D image over the deep image); `Target Input Alpha` (use Color input's alpha to drive deep transparency; off = RGB only recolors); `Drop Input Zero Alpha` (ignore zero-alpha Color pixels entirely). (p.1016-1017)
- **dResize (`dRz`)** — resizes a deep image's width/height. Input: Image (orange, deep). Controls: `Width`, `Height`. (p.1018-1019)
- **dTransform (`dXF`)** — spatial transform of deep data that preserves depth samples (scale/translate including Z). Inputs: Image (orange, deep); Effect Mask (blue). Controls: `Scale Z` (expand/contract overall depth range); `Translate Z` (+ Sample pick — move an object nearer/farther from camera); `Center X/Y`; `Pivot X/Y`; `Size X/Y`; `Use Size and Aspect` (unlocks combined `Size` + `Aspect` sliders). (p.1019-1020)
- **Image to Deep (`ITD`)** — the reverse of Deep to Image: tags a plain 2D image with deep data so it can be composited alongside true deep data via a `dMerge` node. Input: Input (orange, 2D, required). Controls: `Specify Z` (manual Z depth) or, unchecked, `Z Scale` (expand/contract) + `Z Offset` (+ Sample pick, nearer/farther); `Center X/Y`. (p.1021-1022)

### Deep Image Nodes Common Controls (Settings tab, p.1022-1023)
**Gotcha: this chapter's shared Settings tab is abbreviated compared to every other chapter** — it documents only `Hide Incoming Connections` (hides connection lines in the node tree; drag a connected node into the now-empty input field in the Inspector to hide that line, as long as the source node isn't itself selected — selecting it makes the line reappear), a `Comments` tab (adds a note; shows a red-dot icon + text bubble on the node), and a `Scripting` tab (per-tool script edit boxes, same as elsewhere). ## Deep Pixel Nodes (Chapter 37, p.1024-1039)

**What these are**: nodes that consume AOVs (Arbitrary Output Variables — Z, Normals, UV, etc.) embedded as extra channels in an ordinary 2D rendered image (typically from a 3D renderer or Fusion's own Renderer3D), to do post-process lighting/blur/fog/texture effects. This is a different concept from Chapter 36's true multi-sample-per-pixel Deep Image data, despite overlapping vocabulary (depth, Z, fog).

### Ambient Occlusion (`SSAO`)
Approximates global-illumination contact shadowing as a fast 2D post-effect, using Z + Normals AOVs. Captures only low-frequency occlusion — combine with separate Diffuse/Specular passes for a full lighting solution. (p.1025)
- Inputs: Input (orange — 2D RGBA + Z-Depth + Normals, required); **Camera** (green — a 3D Scene or 3D Camera that rendered the image, required); Effect Mask (blue). No render occurs if Input or Camera is missing.
- Key controls: `Output Mode` — Color (AO composited with incoming image) / AO (pure grayscale AO buffer — white=bright, black=dark; useful for building a custom lighting equation from separate passes). `Kernel Type` — **Hemisphere** (rays cast toward a hemisphere aligned to the surface normal; more realistic; flat surfaces get 100% ambient) / Sphere (rays toward a sphere centered on the shading point; stylistic; flat surfaces get 50% ambient). `Number of Samples` — raise until artifacts disappear (costs render time). `Kernel Radius` — scene-scale-dependent search distance for occluders; too small misses nearby occluders, too large degrades quality (needing far more samples to compensate); scales with the scene's Z magnitude (huge Z values need a large kernel; tiny Z values may need a kernel as small as 0.1). `Lift`/`Gamma`/`Tint` — artistic grading of the AO result.
- Tips/limitations (p.1028): AO assumes opaque objects — has known problems with transparent/translucent receivers or occluders (including anti-aliased edges, which are a form of transparency); split transparent objects into a separate scene and compute AO only on opaque geometry. Don't use on particles unless they're solid opaque geometry. For anti-aliased AO, enable HiQ on the Z and Normals passes in Renderer3D. AO is **viewer-dependent** (computed in viewer space) — moving the camera can change the AO value at a fixed scene point, even though physically it shouldn't. Combining multiple AO passes at different Kernel Radii can improve results. AO can be baked into model textures via the OpenGL UV renderer. (p.1025-1028)

### Depth Blur (`DBl`)
Focal-length/depth-of-field simulation, blurring a 3D-rendered image by its Z-channel; can also do general per-pixel blur via any channel. (p.1028)
- Inputs: Input (orange, required — 2D image with a Z channel, used to drive blur amount by region); **Blur Image** (optional — connect to drive blur from any channel of a separate image instead, enabling general 2D per-pixel blur); Effect Mask (blue).
- Key controls: `Filter` — Box / Soften / Super Soften (increasing quality/cost). `Blur Channel` — which channel drives per-pixel blur amount (defaults to main input unless Blur Image is connected). `Lock X/Y`. `Blur Size`. `Focal Point` — visible only when Blur Channel = Z; the simulated in-focus distance (lower = closer to camera). `Depth of Field` — width of the in-focus region centered on Focal Point (e.g. Focal Point 300 + Depth of Field 200 → Z values 200-400 stay in focus). `Z Scale` — scales the Z-buffer to exaggerate/soften the depth effect; scenes with small native Z values may need Z Scale below 1.0. (p.1028-1030)

### Fog (`Fog`)
Simulated depth fog on 3D-rendered images with a Z-buffer, placeable in front of or behind elements by Z plane. (p.1030)
- Inputs: Input (orange, required — 2D image with Z channel); **Blur Image** (green, optional — texture/noise source for the fog's appearance; a solid color is used if not connected); Effect Mask (blue).
- Key controls: `Z-Buffer Near Plane` (+ Pick) — depth where fog thins to nothing. `Far Plane` (+ Pick) — depth where fog becomes fully opaque. `Z Depth Scale` — expands/contracts Z distances to exaggerate the fog effect. `Fog Color` (+ Alpha for fog transparency). `Fog Opacity` — overall opacity across all channels. (p.1030-1032)

### Shader (`Shd`)
Controls lighting/reflection/shading of rendered elements using an embedded Normals channel; **has no effect at all if Normals aren't present.** (p.1032)
- Inputs: Input (orange, required — 2D image with Normals); **Reflection Map Image** (green, optional — projected onto scene elements or ID-selected elements via Common Controls Object/Material ID; best as 32-bit float equirectangular); Effect Mask (blue).
- Light tab: `Ambient` (base light added everywhere, even shadow); `Diffuse` (normal object color, reflected equally all directions); `Specular` (glossy-highlight color toward the eye); `Reflection` (contribution strength — high = mirror-like, low = subtle polish; inert with no reflection map connected); `Reflection Type` — Screen (projected as if onto a screen behind the viewpoint) / Spherical (projected onto a huge surrounding sphere) / Refraction (distorts per scene geometry); `Equator Angle` (left-right light angle); `Polar Height` (top-bottom light angle).
- Shader tab: `Diffuse`/`Specular` checkboxes unlock their falloff curve in the spline window; `In`/`Out` numeric point editing; `Specular Color` tints the specular highlight. (p.1032-1035)

### Texture (`Txr`)
Controls texture mapping of rendered elements using embedded U/V map AOVs; **has no effect without UV channels.** (p.1035)
- Inputs: Input (orange, required — 2D image with UV channels; note: background pixels commonly carry UV = 0,0, which reads as the texture's corner-pixel color — restrict the effect via an Effect Mask keyed off Alpha or Object/Material ID to avoid this); **Texture** (green — replacement texture wrapped over the object); Effect Mask (blue).
- Key controls: `Flip Horizontal`/`Flip Vertical`. `Swap UV` — swaps U and V channels. `Rotate 90`. `U Scale`/`V Scale` — enlarges/shrinks the applied texture. `U Offset`/`V Offset` — slides the texture along the object's geometry. (p.1035-1037)

No Clipping Mode listed (none of this chapter's five nodes reference Clipping Mode on their own Controls tabs either).

## Gotchas and non-obvious behavior

- **Pre-process vs post-process RGBA selectors** (Mental model #3): a node's own Controls-tab channel buttons (Blur's Color Channels, Sharpen's, Unsharp Mask's, Glow's, Brightness Contrast's) skip that channel's computation entirely and are faster; the Common-Controls Settings-tab RGBA buttons compute the full effect then copy the untouched original channel back over the result. They look identical in the UI but behave differently — check which tab you're in.
- **Glow/Soft Glow's Glow Mask is not an Effect Mask**: it pre-filters the source *before* the glow generates, then the glow is merged back over the *unmasked* original — so the glow visually extends past the mask edges even though its source was restricted to inside the mask. A normal Effect Mask instead clips the *final* result.
- **Merge with only Foreground connected outputs nothing** — Background must be connected first (or at all) for any output; this is backwards from what many editors expect and easy to trip over when building a tree top-down.
- **Merge output resolution always equals Background's resolution** — a mismatched Foreground doesn't resize the canvas; use Crop (canvas-only resize) or Resize (image + canvas) upstream of Background if you need a different output size.
- **Dissolve's resolution handling can cause a sudden 4K→8K jump mid-transition** if BG/FG resolutions differ and the slider passes through non-extreme values — worth flagging to a colorist/compositor before it surprises them in a render.
- **Color Corrector / Color Gain / dColorCorrector Equalize or Match forces 16-bit integer processing**, even on a float source — 2D histograms can't represent float's dynamic range. This is a silent depth downgrade if you're mid-way through a 32-bit-float linear pipeline.
- **White Balance's Custom-method pick must be sampled from the un-corrected source**, never from the White Balance node's own output — picking from the live-corrected output creates a feedback loop while dragging and yields a wrong correction.
- **Chromatic Aberration Removal's Estimation Options are inert until a "Show Estimated Fringes" checkbox is checked** — they don't appear grayed out, they're simply not shown, easy to miss when first opening the node.
- **Vector Motion Blur requires float16/float32 vector channels** — an integer-depth vector map can't represent the negative displacement values the node needs.
- **Object ID/Material ID masking (Use Object/Use Material) requires those EXR channels to actually exist** — if missing, Correct Edges and the ID sliders are silently non-functional even though the checkboxes remain clickable.
- **Deep Image chapter's shared Common Controls omits the whole Blend/GPU/Motion Blur/RGBA block** that every other chapter repeats — don't assume a deep node has, e.g., a Motion Blur group just because every other node category does; check the individual node.
- **`Bol` (Channel Booleans, 2D) vs `3Bol` (Channel Boolean, 3D materials)** are different tools for different domains — verify which one a script or user request means before adding a node by abbreviation alone.
- **Ambient Occlusion, Depth Blur, Fog, Shader, and Texture (all Chapter 37) require specific AOV channels to already be embedded** in the upstream 2D render (Z+Normals for AO; Z for Depth Blur/Fog; Normals for Shader; UV for Texture) — none of them convert a plain RGB image into anything; they simply have no effect (or output nothing, for AO) if the channel is absent.
- **Ambient Occlusion is viewer-space and viewer-dependent** — its darkening amount can shift if the camera/viewer position changes, even at a scene point that should physically read the same AO value regardless of viewpoint.
- **Reflection Map Image (Shader node) works best as 32-bit float equirectangular** — an 8-bit non-equirectangular map will visibly distort or clip highlights in the reflection.
- **Texture node UV=0,0 background-pixel gotcha**: unrendered/background pixels commonly report UV coordinates of 0,0, which the Texture node reads as the texture's corner-pixel color, potentially bleeding texture color across the whole background — restrict with an Effect Mask keyed to Alpha or Object/Material ID.

## Recipes / workflows

1. **Linearize → grade → re-gamma** (Gamut, p.954-956): `Gamut` after Loader/MediaIn with `Source Space` = footage's space + `Remove Gamma` checked → grade in linear → second `Gamut` before Saver/MediaOut with `Output Space` = delivery space + `Add Gamma` checked (leave the other side at No Change on each instance).
2. **White-balance via Color Curves eyedropper** (p.939): Pick tool, drag onto a should-be-gray viewer pixel → locks a point on each active channel's spline → drag each point's Out to 0.5.
3. **Generate a range matte from Color Corrector** (p.936): Ranges tab → pick Shadows/Midtones/Highlights in `Range` display, shape the spline → check `Output the Range You See Now as Final Render` → pipe into another node's Effect Mask.
4. **Match one shot's histogram to a reference** (Color Corrector/Curves, p.933-934): feed reference into the green Match/Reference input; Color Corrector → `Histogram Type`=Match; Color Curves → `Match Reference`/`Sample Reference`. Use `Snapshot Match Time` to freeze a moving reference (avoids flicker); `Release Match` to go live again.
5. **Copy/replace an Alpha with Channel Booleans** (p.925-926): pipe new-Alpha source into Foreground, Operation=Copy, To Alpha="Alpha FG" (others=Do Nothing) to replace; or To Red/Green/Blue="Alpha BG" to view existing Alpha as grayscale.
6. **Bake a mask into Alpha** (Channel Booleans, p.926): mask → Foreground input; To Alpha="Matte", others=Do Nothing, Operation=Copy.
7. **Consolidate scattered Merges into one node** (MultiMerge, p.989-992): drag each layer's output onto the MultiMerge node (auto-creates FG input + Layer List row); reorder by dragging in the list; select a row to edit its own Merge tab.
8. **Fix a bad composite edge**: too dark → nudge `Subtractive/Additive` toward Additive or lower `Burn In`; halo/too bright → nudge toward Subtractive or lower `Alpha Gain`. (Merge, p.985)
9. **Depth-composite overlapping 3D layers** (Merge Channels tab, p.988): both inputs need a Z-channel from Renderer3D → enable `Perform Depth Merge` → tune `Foreground Z-Offset`.
10. **Deep-composite two 3D renders**: import deep EXRs (linear colorspace) → `dMerge` (BG + N FG connections) → `Deep to Image` to flatten → apply delivery Gamut only after flattening. (p.996)
